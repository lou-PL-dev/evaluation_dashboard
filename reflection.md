# Reflection

I applied the communication layer principles by keeping every chart focused on business-readable conclusions rather than statistical process. The dashboard reports averages, counts, and rankings by category so a stakeholder can immediately see "which categories underperform" (reasoning and tool_calling scored lowest, in the high-40s) and "how much data backs that up" (via a total-evaluations card). I deliberately left out anything that belongs in the analysis notebook instead: no p-values, standard errors, confidence intervals, beta-distribution parameters, or model-fitting details, even though those existed on the generation side. Filters for category, model version, and date let stakeholders self-serve drill-downs (e.g. "how does gpt-3.5-turbo do on code specifically?") without needing me to rebuild a chart for every question.

If I did this again, I'd add a plain-language annotation directly on the chart for the lowest-scoring category (e.g. "Reasoning: below target — recommend review") so the "so what" is explicit rather than left for the viewer to infer from bar heights, and I'd pull in real evaluation output from an earlier lab instead of synthetic data so the insights would be actionable rather than illustrative.
